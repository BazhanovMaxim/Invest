# Гипотезы и метрики пилота инвестиционной песочницы

Цель пилота — оценить повторное использование песочницы, изменение вовлечённости в приложение Т‑Инвестиций и влияние доступа к тренировкам на оборот реальных сделок. Единица анализа — уникальный пользователь.

## H1. Повторное использование песочницы

**Гипотеза.** Первый опыт работы с песочницей формирует спрос на повторную проверку стратегии.

**Основная продуктовая метрика** — количество уникальных пользователей, самостоятельно запустивших вторую симуляцию в течение 7 суток с момента первого запуска, человек.

**Правило расчёта.** Первым и вторым запуском считаются две отдельные учебные сессии, начатые по действию пользователя. Подходят повтор того же кейса, выбор другого кейса или запуск внешнего робота по инициативе пользователя. Возобновление сессии, технические повторы запросов и фоновые запуски робота исключаются. Каждый пользователь учитывается один раз. Для итогового расчёта берутся только пользователи с полными 7 сутками наблюдения.

**Проверка.** Формируем недельные когорты по дате первого запуска. Для каждой показываем число первых пользователей, число пользователей со вторым запуском и конверсию во второй запуск. Конверсия равна отношению второго числа к первому и позволяет сопоставлять когорты разного размера.

**Источник данных** — журнал учебных сессий с идентификаторами пользователя и сессии, временем старта и признаком инициатора.

## H2. Вовлечённость в приложение Т‑Инвестиций

**Гипотеза.** Доступ к песочнице увеличивает среднее активное время пользователя в приложении Т‑Инвестиций.

**Метрика вовлечённости** — среднее активное время в приложении за 7 суток с момента распределения в экспериментальную или контрольную группу, минут на пользователя.

**Правило расчёта.** Суммируем активные минуты в приложении и делим на всех пользователей соответствующей группы, включая пользователей с нулевым временем. Активные минуты определяем по событиям использования приложения на переднем плане. Фоновую работу, длительный простой и автоматическое выполнение симуляции без участия пользователя исключаем. Порог простоя фиксируем до пилота. Внутри общего времени отдельно выделяем минуты, проведённые в песочнице.

**Проверка.** Сравниваем среднее число активных минут в группах. Долю завершённых симуляций и число повторных запусков используем для интерпретации. Рост времени при снижении доли завершений может указывать на затруднения в работе с продуктом.

**Источник данных** — аналитические события приложения, статусы активности и журнал распределения по группам.

## H3. Оборот реальных сделок

**Гипотеза.** Доступ к тренировкам увеличивает оборот реальных сделок на клиента с действующим брокерским счётом.

**Основная бизнес-метрика** — средний рублёвый оборот исполненных сделок на одного клиента за 30 суток с момента распределения по группам, ₽ на клиента. Для оценки масштаба также фиксируем совокупный оборот каждой группы.

**Правило расчёта.** Складываем рублёвые объёмы исполненных покупок и продаж на реальных счетах по единой методике брокера. Учитываем только исполненную часть каждой заявки. Сумму делим на число всех клиентов группы, включая клиентов без сделок. Учебные сделки, пополнения и выводы средств в оборот не входят.

**Проверка.** Сравниваем средний оборот на клиента в экспериментальной и контрольной группах. Дополнительно смотрим распределение по клиентам и активность до пилота, чтобы оценить влияние отдельных крупных сделок. Для описания поведения прошедших тренировку отдельно можно рассчитать оборот за 30 суток после первой симуляции.

**Источник данных** — банковские данные об исполненных сделках и журнал распределения по группам. Метрика доступна при возможности связать эти данные на уровне клиента.

## Дизайн проверки и критерии успеха

Для проверки H2 и H3 предлагаем случайно распределить подходящих клиентов на группу с немедленным доступом к песочнице и группу с отложенным доступом. В обеих группах отсчёт начинается в момент распределения. В анализ включаются все распределённые участники независимо от того, открывали ли они песочницу. Эффект оцениваем по разнице средних значений с доверительным интервалом. H1 рассчитываем среди пользователей, фактически запустивших первую симуляцию.

До старта фиксируем размер пилота, целевое число пользователей со вторым запуском и ориентир по конверсии для H1. Для H2 и H3 согласуем минимальное практически значимое изменение с учётом базового уровня и доступной выборки.
