# Контракты MVP

Это проект API, а не реализованная OpenAPI-спецификация. Названия и обязательные поля нужны, чтобы UI, робот, агент и движок одинаково понимали состояние.

## HTTP API

| Метод | Путь | Назначение |
| --- | --- | --- |
| POST | `/api/scenarios/prepare` | Подготовить и сохранить версию сценария через AI-Agent |
| POST | `/api/runs` | Создать прогон с начальным портфелем и выбранной целью |
| GET | `/api/runs/{runId}/observation` | Данные, доступные участнику на текущем шаге |
| POST | `/api/runs/{runId}/decisions` | Принять решение и продвинуть виртуальное время на один шаг |
| GET | `/api/runs/{runId}/result` | Получить рассчитанный результат завершённого прогона |
| POST | `/api/runs/{runId}/review` | Подготовить или вернуть сохранённый AI-разбор |
| POST | `/api/product-events` | Записать событие интерфейса с уникальным eventId, повтор не создаёт вторую запись |

Доступ к любому run проверяется по владельцу. Способ выдачи учётных данных для человека и робота выбираем при реализации; схема не предполагает публичный доступ к чужим прогонам.

## Основные структуры

| Контракт | Обязательные данные |
| --- | --- |
| `ScenarioVersion` | ID, версия набора цен, происхождение HISTORICAL/SYNTHETIC, события и шаги раскрытия, версия правил, параметры генерации и хеш содержимого |
| `Run` | ID, владелец, HUMAN/BOT, scenarioVersionId, неизменяемый начальный портфель, цель, текущий шаг, версия состояния, статус |
| `Observation` | runId, step, stateVersion, доступные цены и события, деньги, позиции и активные заявки |
| `Decision` | commandId, expectedStep, expectedVersion, actions[] |
| `Execution` | Заявка, инструмент, шаг, количество, цена, комиссия, версия правил |
| `RunResult` | Начальная и конечная стоимость, результат после расходов, максимальная просадка и достижение выбранной цели |
| `AIReview` | runId, статус, ссылки на метрики и записи журнала, объяснение, предлагаемое изменение, версия модели/промпта |

`ScenarioVersion` является внутренней структурой. Полный ценовой путь не выдаём в публичный Observation. Публикация исторического события и его раскрытие в учебном сценарии являются разными полями времени.

## Пример решения участника

```json
{
  "commandId": "8ae4aca8-bb84-4391-bf57-d6993d9787a1",
  "expectedStep": 12,
  "expectedVersion": 12,
  "actions": [
    {
      "type": "PLACE_ORDER",
      "instrumentId": "SBER",
      "side": "BUY",
      "orderType": "MARKET",
      "lots": 1
    }
  ]
}
```

`instrumentId` в примере является условным кодом из нашего каталога, а не обещанием конкретного идентификатора MCP. Размер лота и доступность инструмента берём из сохранённых параметров. Действия относятся к следующему шагу. Пустой `actions` просто продвигает сценарий.

Повтор той же команды возвращает прежний ответ. Тот же commandId с другим телом даёт `409 COMMAND_ID_REUSED`. Старая версия состояния даёт `409 STATE_CONFLICT`. Некорректное действие или недопустимый параметр даёт `422 INVALID_DECISION`. Конкретный формат ошибок закрепим в OpenAPI при реализации.
