# Как читать и изменять архитектуру

Диаграммы 01 и 02 являются представлениями C4: сначала граница продукта, затем приложения, база и протоколы. Они используют Mermaid flowchart со стереотипами person, software system и container, чтобы сохранить читаемое размещение подписей. Диаграмма 03 раскрывает внутренние модули одного backend. Диаграммы 04-06 показывают порядок вызовов в нотации sequence, 07 является ERD PostgreSQL.

Исходники находятся в `diagrams/*.mmd`, экспортированные SVG в `rendered/`. Править нужно исходник. SVG является результатом рендера и подходит для просмотра в GitHub, браузере и вставки в документы.

Для локальной проверки всех исходников и обновления SVG:

```sh
npm install
npx playwright install chromium
npm run diagrams
```

Рендерер использует локальный Mermaid и локальный headless Chromium. Он проверяет синтаксис каждого исходника, создаёт SVG и сохраняет PNG для визуальной проверки в игнорируемую папку `.tools/diagram-previews/`. Внешние сервисы отрисовки не вызываются.

Для уже установленного окружения доступны переменные `PLAYWRIGHT_MODULE`, `MERMAID_BUNDLE`, `CHROMIUM_EXECUTABLE`. Это пути к библиотеке Playwright, bundle Mermaid и Chromium соответственно. Версии библиотек зафиксированы в корневом `package.json`.

Перед публикацией проверяем: читаемость подписей, направление связей, один backend на container-диаграмме, отсутствие AI-подсказок в sequence прогона и совпадение сущностей с контрактами.
